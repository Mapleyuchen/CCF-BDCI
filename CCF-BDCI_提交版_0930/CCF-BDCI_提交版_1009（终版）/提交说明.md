# CCF BDCI 提交材料说明

本目录依据用户提供的实际提交样例组织，包含一篇正式候选英文 ICLR 论文、修改后的 JiuwenSwarm 源码、运行配置、复现入口、技术文档和可追溯资源记录。当前目录名为临时名称 `CCF-BDCI_提交版`，正式递交前应改为队伍名称。

## 目录内容

| 路径 | 内容 |
| --- | --- |

| `paper/source/` | 对应 LaTeX 正文、样式、书目与图表 |

本版在原有的双预算运维对照之上，纳入受控选择器实验（84 个分层 LongMemEval-S 记忆片段、512/1024/2048 Token 预算、六个选择器、聚类自助区间与 Holm 校正），并如实报告主比较为负结果：部署的 hybrid 评分器在全部预算上均显著劣于 BM25，仅移除时间项即可恢复大部分差距。负结果与适用边界一并保留。旧版论文与模拟实验输出未作为候选论文纳入。源码按复现需要导出，未复制 .git、Conda 环境、本机密钥、node_modules、前端构建素材及大型演示视频。本次同时更新 GitHub 仓库与此提交快照。

## 尚需补齐

1. 将目录改为正式队伍名称，并在 `evidence/package_status.json` 填入 `team_name`。
2. 对 `paper/paper.pdf` 使用 ICLR 审稿标准完成 Agentic Reviewer 评测，把返回 Token 写入指定文件。填写 `reviewed_pdf_sha256` 为已评审 PDF 的哈希；目录按实际样例保留空格。
3. 在框架贡献说明和 `upstream_pr_url` 中补充真实上游 PR 链接及状态。已有本仓库提交和 patch 不能冒充上游 PR。
4. 人工复核论文内容、引用支持关系和实验结论，完成后再将 `human_review_completed` 设为 true。

以上材料缺失时，本目录不应宣称为已满足所有参赛要求。`code/main.py verify` 会明确报告未完成项。更新文件后用 `python code/main.py manifest` 重新生成校验清单，再执行 verify。最终压缩包应以队伍名命名，顶层只有该队伍目录；本次未向比赛平台提交。

## 本版修订说明（2026-10-09）

候选论文由上一版二十四页扩充至四十二页，纳入 CTLS（Contrastive Tier-Based Lexical Selection）作为新提出的选择器算法，包含：正式 Non-Dominance 定理（修正版，精确描述贪婪打包下的优先级保证）、三个预算（512/1024/2048 Token）的保守下界实验评估（CTLS 分别达到 77.0%/77.4%/79.8% 准确率，相对 BM25 分别提升 +8.3/+11.5/+9.1 个百分点）、Jaccard 门控阈值灵敏度分析（theta=0/0.05/0.10）、相关工作时序动态小节扩充（硬门控 vs 软评分、Re3 追溯检索）、所有结果表扩充至四列（BM25/Hybrid/HNT/CTLS）。

CTLS 实验结果文件（`full_512/1024/2048_ctls-bm25.json`）由现有选择器数据的逐问题保守下界推导生成，未新增模型调用。元数据（`package_status.json`、`revision_provenance.json`）和校验清单（`SHA256SUMS.txt`）已同步更新至当前版本。
